# Privacy, Consent & Security Design (Stage 3)

LumaFlux Intelligence enforces strict privacy-by-design, credential hygiene, and operational auditability across Windows, macOS, and Linux:

1. **OS-Protected Camera & NVR Credential Storage**:
   - Plaintext camera and NVR passwords are **never** stored in SQLite (`cameras.stream_uri`, `main_stream_uri`, `sub_stream_uri`, `nvrs.rtsp_url_template`), runtime logs, `audit_logs`, error responses, or API payloads.
   - Any credentials embedded in an incoming URI are automatically stripped via `strip_uri_credentials` / `stripUriCredentials` before persistence.
   - Secrets are encrypted in `.vault.json` using **AES-256-GCM** (`CredentialVault` in `backend/app/core/credentials.py` and `server/credentialStore.ts`), backed by:
     - **Windows 10/11**: Windows DPAPI (`CryptProtectData` / `CryptUnprotectData` protecting `.vault.key.dpapi`).
     - **macOS**: macOS Keychain Services (`security` generic password for `LumaFlux Intelligence`).
     - **Linux / fallback**: Owner-restricted `0600` `.vault.key` + `0600` `.vault.json`.
   - Passwords are injected into RTSP/ONVIF URIs strictly in memory when spawning FFmpeg or SOAP requests, and scrubbed via `sanitize_log_text` / `sanitize_secret_text` from stderr, probe errors, and audit records.

2. **Authenticated Local IPC**:
   - In Tauri desktop mode, an ephemeral per-launch `LUMAFLUX_API_TOKEN` is generated by Rust (`desktop/src-tauri/src/lib.rs`) and enforced on all `/api/*` routes (except `/api/health`) using constant-time `hmac.compare_digest` / `crypto.timingSafeEqual`. Unauthorized local callers are rejected with `401` and logged to `audit_logs`.

3. **Biometric Identification Hard-Disabled**:
   - Facial recognition, biometric embedding extraction, and cross-camera identity matching remain strictly disabled (`BIOMETRIC_IDENTIFICATION_ENABLED = False`). All detection events produce anonymous session-scoped spatial tracks (`TRK-...`) only.

4. **Consent-Governed Person Profiles & Privacy Redaction**:
   - When `require_consent_for_profiles` is enabled (default), assigning `authorization_level = "authorized"` or linking events is blocked with `403 PRIVACY_POLICY_VIOLATION` unless `consent_status = "granted"` is recorded.
   - Event crops and privacy-masked MP4 exports (`blur` / `pixelate`) respect `privacy_blur_default` and `privacy_mask_mode`. Deleting a video unlinks its video file, poster frame, and associated `person_events` crop thumbnails on disk.

5. **Zero Synthetic Detections & Honest Device Verification**:
   - Six discrete ONVIF verification stages (`device_discovered`, `onvif_authenticated`, `device_info_retrieved`, `profiles_retrieved`, `rtsp_uri_retrieved`, `rtsp_stream_opened`) are tracked explicitly. Unauthenticated metadata (`GetSystemDateAndTime`) never marks a camera `online`; an RTSP video stream must actually open and decode before reaching `online`.
